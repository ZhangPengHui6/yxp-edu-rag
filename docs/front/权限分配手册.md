## 0. 一句话结论

平台采用 **RBAC + 租户隔离**：角色决定权限码，权限码决定菜单、路由、按钮与接口。
**前端拦截只负责体验，后端接口鉴权才是唯一裁决者**；任何绕过前端的请求都必须在后端被拒绝并写入审计。

## 1. 权限模型

### 1.1 六层边界

| 层级 | 载体 | 作用 | 无权时的表现 |
|---|---|---|---|
| 菜单 | `src/layouts/menu.ts` | 隐藏无权进入的模块 | 菜单项不渲染 |
| 路由 | `meta.permission` + 全局守卫 | 阻止手输 URL 直达 | 跳转 `/403` |
| 按钮 | `v-permission` / `auth.has()` | 隐藏或禁用操作入口 | 元素移除 / 置灰 |
| 接口 | 后端鉴权中间件 | 最终裁决 | HTTP 403，`code=40301` |
| 数据 | `tenant_id` + 数据范围 | 行级隔离 | 空结果或 403 |
| 审计 | `audit_log` | 事后追溯 | 记录 `security.denied` |

### 1.2 权限码规范

- 格式固定为 `module.action`，全小写、点分隔，例如 `publish.commit`。
- `module` 与侧边栏一级模块一一对应：`dashboard / ingestion / textbook / question / knowledge / annotation / review / publish / evaluation / iam`。
- `action` 优先复用 `view / create / edit / delete`，业务动作直接使用动词（`resolve / decide / merge / commit / rollback / run`）。
- `*` 是唯一通配符，**只授予超级管理员**；业务判断一律走 `has()`，不得在页面里直接比较 `permissions[0] === '*'`。
- 权限码是前后端与审计共享的**稳定契约**：上线后不重命名；确需废弃时保留编码并标注停用，避免历史审计断链。

### 1.3 判定语义

| 写法 | 语义 |
|---|---|
| `auth.has('publish.commit')` | 拥有该权限码 |
| `auth.has(['iam.user', 'iam.role'])` | **任一满足**（OR），不是全部满足 |
| `auth.has()` / `auth.has([])` | 放行（仅用于公开页或基础动作） |
| `permissions` 含 `*` | 恒为真 |

`/system` 路由与“系统设置”菜单使用数组语义：只要拥有任一 `iam.*` 权限即可进入，进入后再按 Tab 过滤。

## 5. 数据范围与租户隔离

### 5.1 基本原则

- **租户来自令牌，不来自请求参数**：后端从登录态解析 `tenant_id`，忽略请求体或查询串中的 `tenant_id`，防止越权拼接。
- 除 `super_admin` 的租户管理外，所有列表、详情、统计查询都必须带 `tenant_id` 条件。
- 前端不保存数据范围（scope），只保存后端下发的权限码；数据范围每次由后端根据令牌推导。
- 跨租户访问统一返回 403（或 404 隐藏资源存在性），不得返回空页掩盖越权。

### 5.2 数据对象范围

| 对象 | 可见范围 | 写入约束 |
|---|---|---|
| 教材 / 章节 / 授权 | 本租户；按学科、学段过滤 | 仅 `textbook.*` 写权限 |
| 题目 / 变式 / 去重对 | 本租户；审核中内容仅控制台可见 | 仅 `question.*` 写权限 |
| 知识点 / 证据链 / 覆盖率 | 本租户；按学科、章节组织 | 仅 `knowledge.*` 写权限 |
| 入库任务 / 原始文件 | 本租户；预签名 URL 短时有效 | 仅 `ingestion.*` |
| 校对任务 | 本租户；按分配人或队列可见 | 仅 `annotation.resolve` |
| 审核任务 | 本租户；审核人不得审核本人提交 | 仅 `review.decide/batch` |
| 发布单 / 索引别名 | 本租户；别名全局唯一 | 仅 `publish.*` |
| 评测数据集 / 运行 | 本租户 | 仅 `evaluation.*` |
| 用户 / 角色 / 字典 | 本租户 | `iam.user/role/dict` |
| 租户 | 全平台 | 仅 `iam.tenant` |
| 审计日志 | 本租户（超管可跨租户） | 只读，禁止改删 |

### 5.3 当前实现状态（POC）

| 控制点 | 前端 | 后端 | 说明 |
|---|---|---|---|
| 租户隔离 | 登录返回单一租户，界面不提供切换 | 待实现 | 必须按令牌过滤 |
| 审核人 ≠ 提交人 | 未实现 | 待实现 | 生产必须补齐，见 §8.2 |
| 发布提交与回滚双人复核 | 未实现 | 待实现 | 生产建议，POC 允许单人 |
| 授权到期拦截 | 展示授权状态 | 待实现 | 到期教材应禁止进入发布候选 |
| 审计只读 | 仅提供查询 | 待实现 | 追加写，不可修改 |

## 6. 前端实现说明

### 6.1 登录与权限下发

1. `POST /auth/login` 返回 `{ token, user }`，`user.permissions` 为该角色展开后的权限码数组。
2. 令牌与用户信息分别存入 `localStorage`：`yxp_admin_token`、`yxp_admin_user`。
3. 页面刷新时若本地无用户信息，守卫调用 `GET /auth/profile` 重新拉取。
4. 接口返回 `40101` 时清除本地登录态并跳转 `/login?redirect=<当前路径>`。
5. 角色调整后，本地缓存的 `user.permissions` 不会自动更新，**需重新登录或清除缓存**才能生效。

### 6.2 路由权限表

| 路由 | 页面 | `meta.permission` |
|---|---|---|
| `/login` | 登录 | 公开 |
| `/dashboard` | 工作台 | `dashboard.view` |
| `/ingestion` | 内容接入 | `ingestion.view` |
| `/textbooks` | 教材 | `textbook.view` |
| `/questions` | 题库 | `question.view` |
| `/knowledge` | 知识点 | `knowledge.view` |
| `/annotation` | 校对 | `annotation.view` |
| `/review` | 审核 | `review.view` |
| `/publish` | 发布 | `publish.view` |
| `/evaluation` | 评测 | `evaluation.view` |
| `/system` | 系统设置 | `iam.user` / `iam.role` / `iam.dict` / `iam.tenant` / `iam.audit`（任一） |
| `/403` | 无访问权限 | 公开 |

守卫顺序：公开页放行 → 未登录跳登录 → 拉取用户 → 权限不足跳 `/403`。
已登录访问 `/login` 会自动回到 `/dashboard`；未知路径按 `/dashboard` 处理。

### 6.3 菜单过滤

`src/layouts/menu.ts` 中每个菜单项都带 `permission`，`AdminLayout` 渲染前用 `auth.has()` 过滤。
分组标题（知识生产 / 质量控制 / 发布运营 / 平台）在组内全部无权限时不显示。
菜单只影响可见性，**不能替代路由守卫**：用户仍可能直接输入 URL。

`v-permission` 两种模式：

```vue
<!-- 无权限移除：适用于有破坏性、非必需的按钮 -->
<el-button v-permission="'publish.commit'">提交发布</el-button>

<!-- 无权限禁用：适用于需要保留布局占位的操作 -->
<el-button v-permission.disable="'publish.commit'">提交发布</el-button>
```

### 6.5 页面内二次判断

- 系统设置：`TABS` 带 `permission`，先过滤 Tab 再加载数据，避免无权用户触发 `iam.*` 请求。
- 内容接入：上传区使用 `auth.has('ingestion.create')` 控制渲染，关闭入口时不发起预签名请求。
- 知识点：覆盖分析按钮受 `knowledge.coverage` 控制，未授权角色看不到分析入口。

### 6.6 新增权限的落地清单

1. `src/constants/permissions.ts` 增加权限码定义。
2. 在对应 `ROLES` 中分配；涉及全部角色时同步 `VIEW_PERMISSIONS`。
3. 路由 `meta.permission` 加码（若是新页面）。
4. `src/layouts/menu.ts` 加菜单项与权限。
5. 页面按钮加 `v-permission`，区块用 `auth.has()`。
6. 后端对应接口加鉴权注解，并补 403 用例。
7. 更新本手册 §3、§4、§6.4、§7。
8. 用两个角色各跑一遍：有权限可见可用，无权限不可见且接口 403。

### 7.1 错误约定

| 场景 | HTTP | `code` | 前端行为 |
|---|---|---|---|
| 未登录 / 令牌过期 | 401 | `40101` | 清除登录态，跳登录页并带 `redirect` |
| 已登录但无权限 | 403 | `40301` | 保留登录态，提示无权限；直接访问路由则跳 `/403` |
| 资源不存在或跨租户 | 404 | `40401` | 提示不存在（不暴露是否存在） |
| 参数错误 | 400 | `40001` | 展示后端 `message` |
| 服务异常 | 500 | `50001` | 通用错误提示，记录 `request_id` |

响应统一信封：`{ code, message, data, request_id }`，`code=0` 为成功。
排查问题时以 `request_id` 串联前后端日志与审计。

### 7.2 后端校验要求

1. **不信前端**：隐藏按钮不是安全边界，接口必须独立校验权限码。
2. **不信请求体**：`tenant_id`、`permissions`、`created_by` 一律从令牌推导。
3. **先认证后授权**：401 与 403 语义严格区分，避免前端误清理登录态。
4. **越权留痕**：403 写入审计 `security.denied`，包含用户、权限码、目标接口、IP。
5. **Mock 免责**：开发期 Mock 适配器只校验登录态，不校验权限码；它只用于演示，不能作为生产鉴权参考。

## 8. 典型流程与权限链

### 8.1 POC 主流程

| 阶段 | 操作 | 所需权限 | 执行角色 |
|---|---|---|---|
| 入库 | 预签名上传、创建任务 | `ingestion.create` | 教研管理员 |
| 入库 | 失败重试 / 终止 | `ingestion.retry` / `ingestion.cancel` | 教研管理员 |
| 校对 | 处理低置信度块 | `annotation.view` + `annotation.resolve` | 校对员、教研管理员 |
| 审核 | 通过 / 驳回 / 批量通过 | `review.view` + `review.decide` / `review.batch` | 审核员、教研管理员 |
| 发布 | 新建发布单 | `publish.create` | 发布管理员、教研管理员 |
| 发布 | 暂存、提交、回滚 | `publish.commit` / `publish.rollback` | 发布管理员、教研管理员 |
| 评测 | 发起发布前评测 | `evaluation.run` | 发布管理员、教研管理员 |
| 查看 | 查看报告与发布单 | `evaluation.view` / `publish.view` | 全部角色（除校对员无发布视图） |

### 8.2 职责分离（生产必须开启，POC 未实现）

| 规则 | 目的 | 落地方式 |
|---|---|---|
| 审核人 ≠ 提交人 | 防止自审自过 | 后端比对提交人与审核人，相同则 403 |
| 发布 commit ≠ 同一人连续操作 | 降低误发布风险 | 双人复核或二次验证码 |
| 内容编辑与发布权限分离 | 防止未审内容直接上线 | 生产将 `kb_admin` 拆为编辑、审核、发布三个角色 |
| 超级管理员不参与日常业务 | 缩小高权限面 | 超管账号仅用于 IAM 与应急，业务由岗位角色执行 |
| 校对员与审核员分离 | 识别结果与审核结论独立 | 两个角色不合并授予同一人 |

> 上述规则需前后端配套：前端提示“无权限”，后端强制拒绝。POC 阶段以流程约定为主，不作为验收阻塞项，但上线前必须补齐。

## 9. 账号生命周期

### 9.1 开通

1. 申请人提交：姓名、所属租户、岗位、所需角色、使用期限。
2. 审批人：本租户 `super_admin` 或平台管理员；涉及 `iam.tenant`/`iam.audit` 的账号必须平台审批。
3. 创建账号并绑定角色，**不单独分配权限码**。
4. 首次登录强制改密；POC 演示账号除外（仅限本地 Mock）。

### 9.2 变更

- 角色变更视同重新授权，需重新审批并写入 `iam.role.update` 审计。
- 临时提权必须设置到期时间；到期自动回收。
- 权限调整后通知用户重新登录，前端缓存的权限不会热更新。

### 9.3 回收

| 场景 | 动作 | 时限 |
|---|---|---|
| 离职 / 转岗 | 禁用账号、撤销令牌、移除角色 | 当日 |
| 项目结束 | 禁用 POC 账号，保留审计 | 项目验收后 7 日内 |
| 长期未登录（>90 天） | 自动禁用，需重新激活 | 每季度复核 |
| 越权尝试（≥3 次/日） | 临时锁定并通知安全负责人 | 即时 |

### 9.4 定期复核

- 每季度导出 `用户 × 角色 × 权限数` 清单，由租户管理员确认。
- 重点检查：`super_admin` 数量、`kb_admin` 是否仍符合最小授权、离职账号是否残留。
- 复核记录归档，保留至少 1 年。

## 10. 审计与追溯

### 10.1 审计字段

| 字段 | 说明 |
|---|---|
| `id` | 审计 ID |
| `actor` | 操作人姓名（关联用户 ID） |
| `action` | 动作码，与权限码同名或为资源动作 |
| `target` | 目标对象 ID |
| `ip` | 来源 IP |
| `createdAt` | 操作时间 |

### 10.2 必须审计的动作

| 类别 | 动作码 |
|---|---|
| 登录 | `auth.login`、`auth.logout` |
| 入库 | `ingestion.job.create`、`ingestion.job.retry`、`ingestion.job.cancel` |
| 教材 | `textbook.license.update`、`textbook.create`、`textbook.edit`、`textbook.delete` |
| 题库 | `question.import`、`question.update`、`question.variant`、`question.dedupe` |
| 知识点 | `knowledge.create`、`knowledge.edit`、`knowledge.merge` |
| 校对 | `annotation.resolve` |
| 审核 | `review.decide`、`review.batch` |
| 发布 | `publish.create`、`publish.stage`、`publish.commit`、`publish.rollback` |
| 评测 | `evaluation.run`、`evaluation.dataset.update` |
| 系统 | `iam.user.create/update/disable`、`iam.role.update`、`iam.dict.update`、`iam.tenant.update` |
| 安全 | `security.denied`（403）、`auth.login.failed` |

### 10.3 审计规则

- 审计表**追加写**，不提供修改、删除接口；在线保留 180 天，归档后按合规要求保存。
- 不记录密码、令牌、文件正文；只记录对象 ID 与变更摘要。
- 用户只能查看本租户审计；跨租户查询仅 `super_admin`。
- 导出审计需平台管理员操作，并记录导出行为本身。
- 高敏操作（提交发布、回滚、下架教材、授权变更）在界面二次确认，确认结果写入审计摘要。

## 12. 常见问题

**Q1：登录后菜单不全，是权限配置错了吗？**
先看角色；菜单按 `permission` 过滤，属正常。若应有权限却没有，检查 `ROLES` 分配与后端下发的 `permissions` 是否一致。

**Q2：后台改了角色，前端没变化。**
权限缓存在 `localStorage`。重新登录，或清除 `yxp_admin_user` 后刷新页面。

**Q3：403 和 401 有什么区别？**
401 是“不知道你是谁”，前端清理登录态并跳登录；403 是“知道你是谁但不允许”，保留登录态，提示或跳 `/403`。

**Q4：按钮都隐藏了，为什么后端还要校验？**
前端代码可被绕过（改本地缓存、直接调接口）。隐藏按钮只改善体验，安全边界在后端。

**Q5：数组权限是“全部满足”吗？**
不是。`auth.has(['a','b'])` 与 `v-permission="['a','b']"` 均为**任一满足**。需要全部满足时写两个指令或自定义判断。

**Q6：超级管理员的权限数是 37 还是 1？**
存储的是 `['*']`，展示时按全部权限码计数（37）。业务判断统一使用 `has()`，不要按数组长度判断。

**Q7：为什么校对员看不到发布菜单，但审核员能看？**
审核员需要核对“该变更是否已进入发布候选”，因此保留 `publish.view` 只读；校对员不参与发布链路，故不授予。

**Q8：能否给某个人单独加一个权限？**
不能。权限只挂在角色上；临时需求通过新建临时角色并设置到期时间解决，避免出现无法审计的个人权限。
