## 1. 范围与定位

本服务是 K12 知识管理平台的**管理端后端**，面向前端 `yxp_rag_front`，承担以下职责：

- 身份认证、租户隔离、RBAC 权限校验；
- 教材 / 题目 / 知识点等内容资产的查询与维护；
- 低置信度校对、审核任务流转；
- 入库任务的创建、进度、重试、终止；
- 发布单的创建、暂存、提交、回滚（向量别名两阶段切换）；
- 发布前评测与评测报告；
- 工作台聚合、字典、审计日志查询。

**不包含**：学员侧检索问答 `/v1`、会话/学情/错题、在线 RAG 召回与生成。该部分已拆为同仓库的独立进程 `apps/kb-api`（端口 8001），只读 MongoDB / Milvus / MinIO，不读 PostgreSQL；管理端表结构变化不会影响在线服务。设计见 [学员检索问答服务设计.md](学员检索问答服务设计.md)。

POC 语料为学而思《高中数学知识手册》（88 页）与《高中物理知识手册》（77 页）。本阶段只实现管理流程与契约，不实际执行 OCR / 数据加工流水线。

### 2.1 与知识库服务的关系

| 数据 | 管理端 | 知识库 `/v1` |

### 4.1 依赖方向

```
api/v1/*.py
   │  只解析参数、挂权限、调 service
   ▼
modules/<module>/service.py
   │  用例、事务、幂等、审计、事件
   ├──▶ domain/*         纯函数，无 I/O，不 import FastAPI / DB / 云 SDK
   ├──▶ modules/<module>/repository.py   只做数据访问
   └──▶ infra/*          适配器
```

约束：

- 事务边界在 `service`，不在 router；不在 repository 内 commit。
- 不跨模块直接调用另一个模块的 repository；跨模块读通过对方 `service`。
- `domain` 不依赖框架，便于纯单元测试。
- `api` 不写业务判断，只做 DTO 转换与依赖注入。
- 异步任务复用同一 service / pipeline，避免两套业务逻辑。

### 4.2 请求上下文

`main.py` 的 HTTP 中间件为每个请求生成或透传 `X-Request-Id`，写入 `ContextVar`；structlog processor 自动附加该字段。审计日志同样读取当前 `request_id` 与客户端 IP。

- 活动集合：`chunks_live`（`MILVUS_CHUNKS_COLLECTION`），保存片段正文、过滤字段与 dense/sparse 向量；`struct` 节点通过 `app/infra/chunk_store.py` 直接 `upsert / delete / query`，Mongo 不再保存 chunk；

- POC：`TASK_MODE=inline`，`asyncio.create_task` 在 API 进程内执行同一套 pipeline，测试可 `drain_inline_tasks()` 等待完成。

## 7. 关键流程

### 7.1 登录与鉴权

```
POST /auth/login
  → 校验用户名/密码（Argon2）
  → 签发 JWT（sub=user_id，含 tenant_id，默认 720 分钟）
  → 更新 last_login_at（PG）
  → 返回 token + 用户信息（含权限码）

后续请求
  → Authorization: Bearer <token>
  → decode JWT
  → load_principal：用户、角色、权限、租户
  → require("xxx") 校验权限
  → 业务 service 以 tenant_id 收口数据
```

- 401 表示未登录/令牌无效；403 表示已登录但缺少权限，两者分开。
- `super_admin` 的权限集合含 `*`，`CurrentUser.has()` 对通配符放行。
- POC 的退出登录是无状态返回；生产应把 `jti` 写入 Redis 黑名单。

### 7.2 入库任务

```
POST /ingestion/uploads     → 预签名 URL
PUT  <signed url>           → 文件直传
POST /ingestion/jobs        → 创建任务（可带 Idempotency-Key）
  → PG 写 job + 5 个 step
  → 派发后台任务
GET /ingestion/jobs/{id}    → 轮询进度
POST .../retry | .../cancel → 失败/终止
```

步骤固定为：`upload → ocr → split → struct → quality`，由 LangGraph 状态机编排（`modules/ingestion/graph/`，节点设计见《LangGraph 节点编排》）。`OCR_PROVIDER=auto|mineru|qwen_vl` 时执行真实流水线：

1. `upload`：按 `source_uri` 从 MinIO/本地存储读取原始文件；
2. `ocr`：`auto` 优先调用 MinerU v4 云端 API（`model_version=vlm`，公式/表格开启），轮询批次结果并下载 ZIP，解析 `*content_list.json`；鉴权支持 `MINERU_TOKEN` 直接作 Bearer，也支持 OpenXLab `MINERU_ACCESS_KEY_ID` / `MINERU_SECRET_ACCESS_KEY`——先 `POST .../auth` 取 nonce 与签名算法，用 SK 做 HMAC-SHA1 得到 `d`，再 `POST .../getJwt` 换 JWT，内存缓存并在到期前用 `refresh_token` 续期，失败则重新登录。MinerU 失败或无凭据时自动降级到 Qwen-VL（PyMuPDF 逐页渲染，图片经 OpenAI 兼容接口送入千问视觉模型）；
3. `split`：把带页码锚点的 Markdown 切成分块（保留标题路径、公式、表格）；
4. `struct`：标题路径先构建知识点树，再由 Qwen（`LLM_DEFAULT_MODEL`，默认 `qwen/qwen3.7-flash`）按批次抽取题目与知识点——题型、选项、答案、解析、难度、来源页码和知识点名称；LLM 结果与“例/例题/变式/练习”规则抽取按题干去重合并，LLM 调用失败时回退纯规则结果。`EMBEDDING_PROVIDER=bge_m3` 时再用本地 BGE-M3 为片段生成 1024 维 dense + sparse 词权重、为题目生成题干/解答向量；片段连同向量写入 Milvus `chunks_live`，题目与知识点写入 Mongo；
5. `quality`：统计有效片段比例、答案覆盖率；对每道题取候选片段（同页优先 + 字符二元组重合度）做重排，写 `evidence_chunk_ids` / `evidence_score`。七牛云没有独立 rerank 接口，默认用千问模型打分（`RERANK_PROVIDER=qwen_llm`），也可显式切回 DashScope `qwen3-rerank`。

`OCR_PROVIDER=placeholder`（测试默认）只推进状态机，不做外部调用。真实解析失败时任务进入 `failed`，`error_code=PROVIDER_UNAVAILABLE` 并给出缺失配置或上游错误信息，便于直接重试。LLM 结构化或重排失败只降级该步骤，不会让任务失败；`EMBEDDING_PROVIDER=bge_m3` 时向量化失败会让任务失败并提示缺失依赖/模型路径（`EMBEDDING_PROVIDER=off` 时跳过）。`job.stats` 记录 `llmStructuring` / `llmQuestions` / `llmKnowledgePoints` / `rerankedQuestions` / `rerankProvider` / `embeddedChunks` / `embeddedQuestions` / `embeddingProvider`。

任务状态机：`pending → running → succeeded | failed | canceled`；`failed → pending` 仅通过重试进入。

### 7.3 校对与审核

- 校对任务按低置信度区块组织，提交后更新 Mongo 区块状态并写审计；
- 审核任务覆盖题目、知识点、教材变更；
- 题目审核通过后写 Mongo `review_status=approved`，**尚未发布**；
- 驳回则回到 `draft`；
- 审核决定写 `audit_log`，并通过 `outbox_event` 发出 `review.decided`。

### 7.4 发布（两阶段）

```
POST /publish/orders                 → 草稿：校验项 + 变更摘要 + 新版本号
POST /publish/orders/{id}/stage      → 写/验证新的 chunks_<v>、questions_<v>
POST /publish/orders/{id}/commit     → 全部校验通过后切换两个别名
POST /publish/orders/{id}/rollback   → 别名切回上一版本
```

1. **草稿**：统计待写入向量数，计算引用完整性、评测结果等检查项，生成 `index_version_new`（UTC 时间戳），状态 `draft`。
2. **暂存**：`build_version_index()` 从 Milvus `chunks_live` 读取全部片段、从 Mongo 读取已发布题目，补齐缺失的 BGE-M3 向量，重建 `chunks_<version>` / `questions_<version>`；随后 `VectorIndex.stage()` 校验集合存在并返回条目数。引用完整性或别名校验失败 → `failed`；成功 → `staged`，不触碰线上别名。
3. **提交**：再次执行全部检查；依次把 `chunks_active`、`questions_active` 切到新集合；PG 发布单置 `published`，Mongo 中 `approved` 题目转为 `published`、`reviewing` 教材转为 `published`；写审计与 `asset.published` 事件。
4. **回滚**：仅允许 `published`；把两个别名指回 `index_version_old`，状态 `rolled_back`，保留新集合供排查。

幂等性：`stage` 对已 `staged` 直接返回；`commit` 对已 `published` 直接返回；`rollback` 对已 `rolled_back` 直接返回。非法状态返回 `INVALID_STATE`（409）。

一致性说明：这是跨 PG / Mongo / Milvus 的**非分布式事务**。向量切换成功但 PG 提交失败时，发布单仍停留在 `staged`，可通过再次提交修复；POC 不实现自动补偿，生产应以 outbox + 对账任务补齐。

### 7.5 评测

- 数据集与用例存 PG；
- POC 以“金标知识点是否有已发布题目覆盖、覆盖题目质量分”计算 Recall / 准确率 / 引用准确率代理指标；
- 结果写 `eval_run` / `eval_result`；
- 最新一次评测参与发布校验：`recall >= EVAL_RECALL_THRESHOLD`（默认 0.85）且状态非 `failed`。

|---|---|---|---|

所有响应带 `X-Request-Id` 头；请求可透传该头用于链路串联。

### 8.3 分页

管理前端契约使用页码分页：

- 请求：`?page=1&pageSize=10`（`pageSize` 上限 100）；
- 响应：`{ "items": [], "total": 0, "page": 1, "pageSize": 10 }`。

《总纲》建议 `limit + cursor`。本项目以已落地的前端契约优先，深分页风险在 POC 数据量下可接受；生产规模上来后应增加 cursor 接口或限制最大页码。

### 8.4 时间格式

管理端返回 `YYYY-MM-DD HH:MM`（UTC），例如 `2026-10-24 10:24`。这是对《总纲》“ISO 8601”的**显式偏差**：前端表格按原样展示，改格式会破坏现有页面。存储始终为 UTC，需要机器读取的场景由 OpenAPI 模型另行提供。

### 8.5 题目状态兼容

内部状态：`draft | reviewing | approved | published | deprecated`。

管理端只暴露四种：`draft | reviewing | published | archived`。

- `approved`（审核通过、尚未随发布单上线）→ 映射为 `reviewing`；
- `deprecated` → 映射为 `archived`；
- 列表筛选 `reviewing` 时同时匹配内部 `reviewing` 与 `approved`。

原因：前端 `StatusTag` 与 `constants/status.ts` 只认识四种状态；直接暴露第五种会显示原始英文并破坏筛选。发布提交时 `approved → published`，语义仍然正确。

### 8.6 幂等

- 创建入库任务支持 `Idempotency-Key` 请求头；同租户同 key 返回已有任务；
- 发布单的 `stage / commit / rollback` 按状态幂等；
- 其余查询天然幂等。

## 10. 状态机与领域规则

### 10.1 状态机（`app/domain/asset.py`）

| 对象 | 状态 |
|---|---|
| 资产 | `draft → parsing → parsed → annotated → reviewing → approved → published → deprecated` |
| 入库任务 | `pending → running → succeeded / failed / canceled`；`failed → pending` |
| 审核 | `pending → in_review → approved / rejected / transferred` |
| 发布单 | `draft → staged → published → rolled_back`；`draft / staged → failed`；`failed / rolled_back → draft` |

状态机是纯函数，非法迁移抛 `InvalidState`（409）。服务层在写库前校验，避免依赖数据库约束才发现问题。

### 10.2 题目规则（`app/domain/question_rules.py`）

- 文本归一化 + SimHash64；Hamming 距离 ≤ 3 视为重复候选；
- 完全一致时相似度为 1.0，否则按 `1 - distance / 16` 估算；
- 质量门禁：题干、答案、知识点、质量分 ≥ 0.6、审核通过，任一缺失即不可发布；
- 题型/难度在中文标签与内部枚举之间双向映射。

### 10.3 发布规则（`app/domain/publish_rules.py`）

发布检查项固定为四项：引用完整性、向量索引、别名可用性、抽样评测。`stage` 只强制前两项与别名，`commit` 要求全部通过。阶段展示由纯函数根据状态生成，前端不自行拼装。

| 能力 | POC 默认 | 生产切换 | 切换条件 |

## 12. Provider 契约

`app/infra/providers/__init__.py` 定义四个 Protocol：

| Provider | 方法 | 说明 |
|---|---|---|
| `OcrProvider` | `parse(content, filename) -> OcrDocument` | 版面 + 公式识别 |
| `LlmProvider` | `complete(messages, temperature, response_format, max_tokens) -> str` | 结构化、变式生成 |
| `EmbeddingProvider` | `embed(texts) -> list[list[float]]`、`embed_documents(texts) -> EmbeddingBatch` | dense 向量 + sparse 词权重 |
| `RerankProvider` | `rerank_with_scores(query, documents, top_n) -> list[(index, score)]` | 精排 |

已实现：

- `MineruOcrProvider`（`providers/mineru.py`）与 `QwenVlOcrProvider`（`providers/qwen_vl.py`），工厂 `get_ocr_provider()` 按 `OCR_PROVIDER` 选择，`get_ocr_fallback()` 提供一次降级；MinerU 支持 token 与 OpenXLab AK/SK 两种鉴权，JWT 在进程内缓存（带锁，避免并发任务重复登录）；
- `QwenLlmProvider`（`providers/qwen.py`）调用 OpenAI 兼容的 `/chat/completions`，默认关闭 thinking 并支持 `response_format=json_object`；
- `QwenRerankProvider` 调用 DashScope 原生 text-rerank；`QwenLlmRerankProvider` 用同一套聊天接口给候选片段打分，适配没有 rerank 接口的网关（如七牛云）；
- `BgeM3EmbeddingProvider`（`providers/bge.py`）通过 FlagEmbedding 加载本地
  `BAAI/bge-m3`，一次前向返回 1024 维 dense 向量与 sparse 词权重；模型懒加载，
  推理放在线程池，`BGE_FP16` 仅在 CUDA 下生效。依赖通过
  `uv sync --extra embeddings` 安装。

`EMBEDDING_PROVIDER=off`（默认）时工厂返回 `UnavailableEmbeddingProvider`，解析只落文本。凭据通过 `MINERU_TOKEN`（或 `MINERU_ACCESS_KEY_ID` + `MINERU_SECRET_ACCESS_KEY`）/ `DASHSCOPE_API_KEY` 注入，仓库根目录 `.env` 与 `apps/admin-api/.env.remote` 均可配置。

## 17. 已知限制与后续工作

1. **学员 `/v1` 是独立进程**：本服务只提供管理 API；RAG 检索与问答由同仓库的 `apps/kb-api` 实现（复用本服务的 Provider / Milvus / Mongo 适配层），会话与学情仍待补齐。
2. **不执行真实 OCR / LLM**：POC pipeline 只推进状态，产物未落库；接入时替换 `pipeline.execute_step`，并复用 `OcrProvider` 契约。
3. **发布不是分布式事务**：PG / Mongo / Milvus 之间无两阶段提交；生产需增加 outbox 消费与对账补偿。
4. **别名检查为 POC 简化**：当前 `_alias_check` 只读取当前别名并始终放行（首次发布提示“提交时创建”），不校验目标集合是否存在、行数与维度；生产应补充这些校验，并在别名不可解析时判定失败。
5. **分页使用 offset**：《总纲》要求 cursor；当前以前端契约为准，大数据量时应补 cursor。
6. **时间输出为分钟精度**：与前端展示契约一致，不是 ISO 8601；机器对接应使用独立字段或直接读库。
7. **退出登录无服务端吊销**：JWT 无状态；生产需 Redis `jti` 黑名单。
8. **审计覆盖为关键写操作**：并非每个字段变更都留痕；生产应按《总纲》6.6 扩展。
9. **上传未做病毒扫描 / 类型深度校验**：POC 仅校验扩展名与大小；生产需接入扫描服务。
10. **`approved` 对外不可见**：为兼容前端四种状态而映射为 `reviewing`；若未来前端支持“已通过未发布”，应改为独立状态并同步 OpenAPI。
11. **回滚只切别名，不回滚资产状态**：`commit` 会把 Mongo 中 `approved` 题目改为 `published`、`reviewing` 教材改为 `published`；`rollback` 仅将 `chunks_active` / `questions_active` 指回旧版本，不会把 Mongo 状态改回。回滚后管理端仍显示新内容为已发布，但学员检索走旧索引。生产若要求状态一致，应在回滚时按发布快照恢复，或改为“内容版本 + 发布单”单向视图。

## 18. 与《概要设计总纲》的契约偏差记录

| 项 | 《总纲》 | 实现 | 原因 |
|---|---|---|---|
| 列表分页 | `limit + cursor` | `page + pageSize` | 已落地前端契约；避免重写页面与类型 |
| 时间格式 | ISO 8601 | `YYYY-MM-DD HH:MM` | 前端表格原样展示 |
| 错误响应 | 仅嵌套 `error` | 扁平字段 + 嵌套 `error` | 前端拦截器读 `code/message`，同时满足总纲 |
| 题目状态 | 五种内部状态 | 对外四种 | 前端 `StatusTag` 仅支持四种 |
| 模块划分 | 含 `index`、`tenants`、`audit` 独立 API | 合并到 `publish` / `iam` | POC 规模下减少空壳模块，边界仍清晰 |
| 迁移 | 全量 Alembic | 初始迁移用 metadata | POC 快速起库；后续增量迁移 |
| 集成测试 | testcontainers | 内存适配器 | Windows 本地零依赖；生产适配器仍保留 |

以上偏差均已在代码注释与本文档中标注，不做隐式行为变化。
