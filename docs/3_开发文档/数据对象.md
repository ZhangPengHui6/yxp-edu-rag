# YXP 数据对象设计

> 版本：v1.0
> 依据：`docs/1_PRD/yxp_prd.md`（v0.4）、`docs/2_概要设计总纲/yxp_概要设计总纲.md`
> 范围：知识管理平台（管理侧）+ 知识库侧只读聚合对象
> 读者：后端、数据、前端开发

---

## 0. 一句话结论

**流程数据进 PG，内容资产进 Mongo，向量进 Milvus，文件进 MinIO，热点与队列进 Redis。**
四类存储之间不建外键、不做分布式事务，靠 `tenant_id` + 业务 ID + `version` + 发布单对齐。

---

## 1. 设计原则

### 1.1 存储分工

| 存储 | 承载 | 特征 | 事务 |
|---|---|---|---|
| PostgreSQL 16 | 用户、权限、任务、审核、发布、评测、审计、outbox | 强一致、状态跃迁、并发控制 | 本地事务 |
| MongoDB 7 | 教材、章节、切片元数据、题目、知识点、授权、租户、运行时记录 | 文档结构灵活、字段可演进 | 单文档原子；跨文档用 `version` 乐观锁 |
| Milvus 2.5 | 切片向量、题目向量、知识点向量 | 高维检索、标量过滤 | 无事务，靠别名切换 |
| MinIO | 原始文件、解析中间产物、图片、导出 | 大对象、预签名直传 | 无 |
| Redis 7 | Celery broker、短时缓存、限流计数、分布式锁 | 可丢 | 无 |

**跨存储一致性**：不做两阶段提交。PG 写状态 + `outbox_event`，由任务推进 Mongo / Milvus，失败可重入。

### 1.2 通用字段

除特别说明，所有业务对象都带以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tenant_id` | string(32) | 租户隔离，所有查询必须带 |
| `created_at` | datetime (UTC) | 创建时间 |
| `updated_at` | datetime (UTC) | 最后更新时间 |
| `created_by` | string(32) | 操作人；系统写入为 `system` |
| `version` | int | 乐观锁版本号，从 1 开始，每次更新 +1 |
| `deleted_at` | datetime \| null | 软删除；查询默认带 `deleted_at is null` |

PG 用 `timestamptz`；Mongo 存 BSON Date（UTC）；API 输出 ISO 8601 带时区。

### 1.3 主键与 ID

统一 **「类型前缀 + ULID」**，26 位，可按时间排序，避免自增 ID 泄露规模。

| 前缀 | 对象 | 示例 |
|---|---|---|
| `tnt_` | 租户 | `tnt_01J9Z6K3M8Q2R4T6V8X0Y2A4C6` |
| `usr_` | 用户 | `usr_01J9Z6...` |
| `rol_` | 角色 | `rol_...` |
| `job_` | 入库任务 | `job_...` |
| `stp_` | 任务步骤 | `stp_...` |
| `ann_` | 校对任务 | `ann_...` |
| `rev_` | 审核任务 | `rev_...` |
| `pub_` | 发布单 | `pub_...` |
| `book_` | 教材 | `book_...` |
| `chp_` | 章节 | `chp_...` |
| `chk_` | 切片 | `chk_...` |
| `q_` | 题目 | `q_...` |
| `var_` | 变式题 | `var_...` |
| `kp_` | 知识点 | `kp_...` |
| `lic_` | 授权 | `lic_...` |
| `ocr_` | OCR 任务 | `ocr_...` |
| `stu_` | 学生 | `stu_...` |
| `conv_` | 会话 | `conv_...` |
| `msg_` | 消息 | `msg_...` |
| `rec_` | 回答记录 | `rec_...` |
| `prac_` | 练习集 | `prac_...` |
| `sub_` | 作答记录 | `sub_...` |
| `wq_` | 错题 | `wq_...` |

生成位置：`app/shared/ids.py`。**禁止**把数据库自增 ID 暴露给前端或写进向量库。

### 1.4 枚举约定

所有状态字段在代码里用 `str` 枚举，在库里存小写短字符串（不用数字），便于排查。

### 1.5 学段字段

PRD 正式范围是初中，但当前语料是高中知识手册。为避免后续迁移，**所有内容对象同时带 `stage` 和 `grade`**：

- `stage`：`primary` / `middle` / `high`
- `grade`：`1`–`12`，字符串

检索必须带 `stage` 过滤，否则高中公式会污染初中库。

```

   │

   │        │                        │
   │        └── lic_ licenses        ├── * question_variants
   │                                 └── * kp_ids ──→ knowledge_points ── * kp_relations
   │
   ├── * ingestion_job ── * ingestion_job_step
   │        └── * annotation_task ── * review_task ── * publish_order ── * publish_item
   │
   ├── * eval_dataset ── * eval_case ── * eval_run ── * eval_result
   │
   ├── * ocr_jobs ── * ocr_results
   └── * students ── conversations ── messages
            └── practice_sets ── submissions
```

**跨存储引用只存 ID，不建外键**：`questions.chapter_id` 指向 Mongo `chapters._id`；片段只存于 Milvus（`chunks_live` 的 `chunk_id` 为主键），题目通过 `knowledge_point_ids` 与知识点关联。

切片只存 Milvus：`struct` 节点写入活动集合 `MILVUS_CHUNKS_COLLECTION`（默认 `chunks_live`），Mongo 不再保存切片。

## 7. 状态机

### 7.1 内容资产

```
draft → parsing → parsed → annotated → reviewing → approved → published → deprecated
              ↘ failed（可重试）
```

| 跃迁 | 触发 | 校验 |
|---|---|---|
| `draft → parsing` | 创建入库任务 | 文件类型、大小、授权 |
| `parsing → parsed` | 解析任务成功 | 页数 > 0、切分非空 |
| `parsed → annotated` | 校对完成 | 低置信度队列清空或人工跳过 |
| `annotated → reviewing` | 提交审核 | 质量门槛通过 |
| `reviewing → approved` | 审核通过 | — |
| `reviewing → annotated` | 驳回 | 需填写 comment |
| `approved → published` | 发布单执行成功 | 索引构建成功 + 别名切换成功 |
| `published → deprecated` | 下架 | 需填写原因 |

**只有发布模块能改 `published/deprecated`**，其他模块只提交动作。

### 7.2 入库任务

`pending → running → succeeded | failed | canceled`

失败可在步骤粒度重试：`failed → running`，`attempt +1`。

### 7.3 审核任务

`pending → in_review → approved | rejected | transferred`

`transferred` 后生成新的 `review_task`，原任务关闭。

### 7.4 发布单

`draft → staged → published`；任一步失败 → `failed`；`published → rolled_back`。

- `staged`：新 Milvus 集合已建好，别名未切。
- `published`：Mongo 状态已改 + 别名已切，两者都成功才算。

### 7.5 OCR 任务

`queued → running → succeeded | failed`

## 9. 版本与发布一致性

一条 `publish_order` 同时记录三个版本：

```json
{
  "book_version": "book_20261024_01",
  "bank_version": "bank_20261024_01",
  "index_version": "idx_20261024_01"
}
```

- `book_version` / `bank_version` 是内容快照标识，写进 Mongo 文档。
- `index_version` 对应 Milvus 集合后缀。
- 出问题按发布单定位：Mongo 查版本 → Milvus 查 `index_version` → 别名回滚。

发布两阶段：

1. **Stage**：写新集合，`publish_order.status=staged`；失败整批丢弃，不影响线上。
2. **Commit**：Mongo 批量改 `status=published` → 切别名 → `status=published`。
   Commit 中途失败时，reconciler 按 `publish_id` 重放，幂等。

## 10. 数据保留与删除

| 数据 | 保留 | 删除方式 |
|---|---|---|
| 会话 / 消息 | 180 天（可配） | TTL 索引 |
| 回答审计 `answer_records` | 1 年 | 定期归档 |
| 检索日志 `question_search_logs` | 90 天 | TTL |
| 错题 / 掌握度 | 学生存在期间 | 按学生删除 |
| 入库原始文件 | 授权期内 | 授权到期删除或归档 |
| 审计日志 | 1 年 | 不含敏感内容 |
| 已删除资产 | 软删除 30 天 | 定时物理清理 |

**删除链路**：Mongo 软删除 → outbox `asset.deleted` → 索引任务删除 Milvus 中对应 ID → MinIO 对象打删除标记。
