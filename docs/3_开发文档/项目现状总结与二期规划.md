# YXP 教育 RAG 项目现状总结与二期规划

> 版本：v1.0　日期：2026-10-26
> 范围：`apps/admin-api`（管理端）、`apps/kb-api`（学员端）、`yxp_rag_front`（运营前端）
> 对比基线：`kb_0515clone`（本地参考实现，`atguigu/` 为实际实现，`src/kb_0515/` 为空壳）
> 方法：代码走查 + 远程生产栈实测（独立主机上的 Milvus / Mongo / MinIO；地址已脱敏）
> 当前数据：教材片段 305 条（高中数学手册）、练习题 30 条（数学 20 / 物理 10，种子数据）

---

## 0. 结论摘要

1. 项目已从参考项目的“单库问答 Demo”演进为**管理端（控制面）+ 学员端（数据面）+ 运营前端**的三角架构，职责边界清晰：管理端是唯一写入方，学员端只读。
2. 参考项目只贡献了**技术骨架**（LangGraph、MinerU、BGE-M3、Milvus 双向量、RRF、Rerank、FastAPI + SSE）；业务语义已整体重写为 K12 的教材/题库/知识点/审核/发布。
3. 当前已经能完整演示一条闭环：**内容接入 → 校对 → 审核 → 版本化发布 → 在线检索问答（带教材/题目引用）**，并已在真实数据上跑通。
4. 相对参考项目，补齐了它完全缺失的四类能力：**版本化发布与回滚、多租户与 RBAC、审计与幂等、评测门禁与测试体系**。
5. 与 PRD 的 P0 相比，学员侧仍缺**拍照识题、分步解题、练习/错题/掌握度**；检索侧仍缺**相关性阈值、真实评测、多轮改写**。
6. 二期建议按三条主线推进：**质量与一致性修复（M1）→ 学员学习闭环（M2）→ 平台化与规模化（M3）**。

  PG  Mongo          Milvus        Mongo

- **管理端与学员端不通过 RPC 耦合**，唯一契约是“共享存储 + 版本号 + Milvus 别名”，管理端故障不影响在线问答，学员端故障不影响内容生产。
- 发布通过 `stage`（建 `chunks_<version>` / `questions_<version>`）→ `commit`（切 `chunks_active` / `questions_active`）实现原子切换，`rollback` 切回旧别名。
- 模型：BGE-M3 本地 CPU（1024 维 dense + sparse），LLM/Rerank 走七牛千问 OpenAI 兼容网关（`qwen/qwen3.7-flash`、`qwen-llm-rerank`）。

### 2.1 管理端 `admin-api`（控制面）

| # | 模块 | 关键接口 | 实现要点 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 认证 / IAM | `/auth/login` `/auth/logout` `/auth/profile`、`/iam/*` | JWT HS256 + Argon2；每请求重新加载权限（撤权即时生效）；6 角色 / 37 权限 | 读接口完成，写接口缺失 |
| 2 | 工作台 | `/dashboard/summary` `/dashboard/todos` | PG 任务计数 + Mongo 资产计数 + 7 日趋势 | 完成 |

| 4 | 教材管理 | `/textbooks`、`/{id}`、`/{id}/chapters`、`PATCH /{id}/license` | 书目 / 章节 / 授权；授权变更写审计 | 读 + 授权编辑完成，CRUD 缺失 |

| 6 | 知识点 | `/knowledge-points/tree`、`/coverage`、`/{id}`、`/{id}/merge` | 树 / 覆盖率 / 证据片段；合并会重挂题目与关系 | 读 + 合并接口完成，编辑缺失 |
| 7 | 校对标注 | `/annotation/tasks`、`/{id}`、`/{id}/resolve` | 低置信度块队列、逐块编辑、解决/标记 | 完成 |
| 8 | 审核 | `/review/tasks`、`/{id}/decision` | 题/教材两类；通过/驳回（必填理由）；回写 `review_status` | 完成，教材侧回写不完整 |
| 9 | 发布索引 | `/publish/orders`、`stage`、`commit`、`rollback` | 4 项检查（引用完整性 / 向量索引 / 别名可用 / 抽样评测）；版本化集合 + 别名切换 | 完成，门禁偏松 |
| 10 | 评测 | `/evaluation/datasets`、`/runs`、`POST /runs` | Recall@10 / 答案准确率 / 引用准确率；结果落 PG | 最小可用，指标为代理值 |
| 11 | 审计 | `/iam/audit` | 所有写操作 append-only；事务性 outbox | 完成 |

**入库管线细节**

- **解析**：MinerU v4 云端（默认）或 Qwen-VL 逐页识别（PyMuPDF 渲染）；失败自动换另一家重试一次。
- **切分**：按 `<!-- page: N -->` 页码锚点与 Markdown 标题构建章节路径；表格 / 公式不拆；句号切分；目标 600 字、重叠 80 字；丢弃 <30 字的碎片；每块带 SHA-256。
- **结构化**：标题树生成知识点（`kp_*`）；LLM（可关）批量抽取题目 JSON，失败批次跳过；正则兜底抽取例题/选项/答案/解析；按归一化题干合并。
- **向量化**：BGE-M3 同时产出 `dense_vector` / `stem_vector` / `solution_vector` / `sparse_vector`；`EMBEDDING_PROVIDER=off` 时只做文本入库。
- **质量**：计算答案覆盖率与长块率，按“同页优先 + 字符 bigram 重叠”重排证据块，写回题目 `evidence_chunk_ids`。

**发布管线**

- 创建发布单时快照检查项与变更数量，版本号 `YYYYMMDD_HHMMSS`。
- `stage` 从 `chunks_live` 与 Mongo 已审核题目重建版本化集合，校验行数。
- `commit` 复跑检查（含评测召回阈值 0.85），切别名，同时把 Mongo 题目 `approved→published`、教材 `reviewing→published`。
- `rollback` 将别名指回 `index_version_old`，数据不删除。

### 2.2 学员端 `kb-api`（数据面）

复用管理端的 Provider / Milvus / Mongo 适配层，不连 PostgreSQL。

| 接口 | 说明 |
| --- | --- |
| `GET /v1/health` | 别名解析、行数、Embedding / LLM / Mongo 状态 |
| `POST /v1/chat` | 完整回答 + 引用 + 置信度 + 分阶段耗时 |
| `POST /v1/chat/stream` | SSE：`meta → citation* → delta* → done \| error` |

**查询图**：`START → confirm → retrieve → rrf → rerank → generate → END`。流式路径复用同一张图但去掉 `generate`，由 HTTP 层直接调模型流式输出，才能做到“先推 meta/citation，再推 delta”。

**四路混合检索**

| 通道 | 集合 / 字段 | 权重 |
| --- | --- | --- |
| 教材稠密 | `chunks_active.dense_vector`（HNSW/COSINE） | 1.0 |
| 教材稀疏 | `chunks_active.sparse_vector`（IP） | 1.0 |
| 题目稠密 | `questions_active.stem_vector`（COSINE） | `KB_QUESTION_WEIGHT=1.0` |
| 题目稀疏 | `questions_active.sparse_vector`（IP） | `KB_QUESTION_WEIGHT=1.0` |

- 融合：`Σ weight/(60+rank)`，窗口 10；其中最多 3 个槽位预留给题目（`KB_QUESTION_QUOTA`），避免 305 条教材挤掉精准匹配的题目。
- 重排：默认 `qwen_llm` 打分，取前 5；429/异常时退化为 RRF 顺序（`rrf-fallback`）。
- 生成：严格依据【教材与题目资料】，句末标注 `[n]`；资料不足明确说明；练习题要求讲推理过程。
- 引用：区分 `source=chunk|question`，教材带书名/页码，题目带题型/难度；摘录截断 1200 字。
- 审计：每次问答写 Mongo `answer_records`（含流式中断），失败不影响回答。

**实测**：问“求函数 f(x)=x³-3x 的极值” → `c1` 命中种子题 `qseed_math_018`（score 1.0），`c2–c5` 为教材导数片段；`retrieval={dense:20,sparse:20,questions:20,fused:10,reranked:5}`；端到端约 5–11 秒（CPU Embedding + 共享网关）。

### 3.4 相对参考项目的实质提升

1. **可运营性**：参考项目没有“发布”概念，改数据即上线；本项目有发布单、检查、快照、回滚。
2. **可追溯性**：从“只有图片 URL”到“书名 + 页码 + 题目 ID + 分数 + 原文摘录”的引用结构。
3. **正确性护栏**：四路检索 + 题目配额 + 范围过滤 + 低置信拒答，减少超纲与张冠李戴。
4. **工程质量**：52 个测试、幂等键、确定性 ID、统一错误信封、结构化日志、请求追踪。
5. **多租户**：`tenant_id` 贯穿 PG/Mongo/Milvus 过滤与 API 层，管理端按角色收敛数据范围。
6. **可演进**：Provider 抽象（OCR/Embedding/LLM/Rerank）都可在“未配置”时降级，POC 不依赖外部服务即可启动。

## 4. 项目亮点

1. **控制面 / 数据面分离**：管理端唯一写入，学员端只读别名，故障隔离，发布不影响在线服务。
2. **不可变版本 + 别名切换**：每次发布生成独立集合，切别名即上线，回滚即切回，不删数据。
3. **教育语义的检索设计**：教材/题目双集合 × 稠密/稀疏四路，题目配额保证“原题命中”不会被长教材淹没。
4. **有依据的回答**：强制行内 `[n]`，引用可区分教材页码与练习题，并在 UI 中可点击定位。
5. **两阶段发布门禁**：stage 校验引用/索引/别名，commit 复跑并叠评测召回阈值，防止“坏索引上线”。
6. **全链路内容生产**：解析（双 OCR）→ 切分 → 知识点/题目抽取 → 校对 → 审核 → 发布，每步有状态、可重试。
7. **多租户与权限内建**：37 个权限点、6 个角色、租户过滤、append-only 审计与 outbox。
8. **Provider 可插拔与优雅降级**：MinerU/Qwen-VL、BGE-M3/off、qwen/dashscope/off；外部依赖缺失时仍可启动与演示。
9. **流式契约稳定**：`meta/citation/delta/done/error` 固定，前端可先渲染证据再流式输出答案。
10. **工程化底座**：52 个测试、幂等、确定性 ID、统一错误码、结构化日志、请求 ID。

### 6.2 二期功能（P1）

**A. 学员学习闭环（最高业务价值）**

- 拍照/图片搜题：OCR + 公式/图形识别 + 多题切分（PRD P0 尚未落地）。
- 分步解题：题干 → 题库原题/相似题 → 标准解析 → 易错点 → 同类练习；保留 `teaching_mode=guided`。
- 练习与判分：按知识点组卷、提交判分、错因归因。
- 错题本 / 掌握度 / 复习队列：`student_id` 已预留，需新增学情集合（学员端唯一写入）。
- 多轮改写与指代消解：把 `rewritten_query` 真正用起来。
- 图片/表格回显：引用中返回 MinIO 签名 URL。

**B. 检索与生成质量**

- `min_score` 相关性阈值，区分“无命中 / 低置信 / 正常”。
- HyDE、知识点图谱扩展召回（作为可选通道，不默认开启）。
- 使用 `solution_vector` 做“解法相似”检索，而不只是题干相似。
- 独立 Rerank 服务或专有 rerank 模型，去掉与生成共享的网关配额。
- 引用去重/压缩、答案一致性校验（同题多次求解一致率）。
- Query embedding 缓存与语义缓存。

**C. 内容生产与发布**

- 教材/题目/知识点写接口与批量导入；批量审核。
- 评测数据集管理、异步评测、真实检索/答质指标（Recall、引用可追溯率、忠实度）。

**D. 平台化**

- API Key 签发/轮换/租户绑定/配额/限流；用量与成本统计。
- 可观测：OTel、指标、慢查询、模型调用成本。

## 7. 风险与依赖

1. **单机生产栈**：Milvus / Mongo / MinIO 跑在本机 VMware 虚拟机，关机后端口“可连”是假象，需先确认 VM 在线。
2. **模型网关限流**：重排与生成共用配额，429 时非流式返回 503、流式发 `error`；二期应拆分并加重试退避。
3. **CPU 推理时延**：BGE-M3 在 CPU 上 retrieve 约 2–4 秒；上 GPU 或独立 Embedding 服务后可显著下降。
4. **数据版权与范围**：当前教材为公开手册、题目为种子数据；正式上线前需完成授权登记与内容合规评审。
5. **评测样本过小**：现有 2 个数据集共 8 条用例，不足以支撑发布门禁，需扩充金标集。
6. **前端密钥**：不要把真实 `KB_API_KEY` 放进前端环境变量，应由同源网关或 BFF 注入。
7. **无前端测试**：仅有 `vue-tsc` 类型检查，建议补关键页面的组件测试与端到端冒烟。
